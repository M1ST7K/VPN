======================================================================
0. OWNER DECISION
======================================================================

The current HotFox design is approved.

Do NOT redesign layouts.
Do NOT move approved fox geometry.
Do NOT reintroduce overlap hacks.

This pass has two goals only:

The product should keep its current visual composition.

======================================================================
1. FONT CHOICE — LOCKED
======================================================================

Use:
ONEST

Source:
official upstream / Google Fonts source only.

License:
SIL Open Font License 1.1.

Use current official Onest source/release.
Do not use random font mirrors.
Do not use unofficial repacks.

Important:
HotFox min Android is API 24.

Do NOT rely on a single variable font file for runtime weight interpolation on all supported devices.

Use static instances:
- Onest Regular 400
- Onest Medium 500
- Onest SemiBold 600
- Onest Bold 700

Preferred implementation:
res/font/onest_regular.ttf
res/font/onest_medium.ttf
res/font/onest_semibold.ttf
res/font/onest_bold.ttf

and one XML font family:
res/font/hotfox_onest.xml

Map:
400 -> Regular
500 -> Medium
600 -> SemiBold
700 -> Bold

If the official package only exposes a variable font:
generate static instances from the official variable source inside the build/workspace using fonttools/varLib.instancer or equivalent.
Do not alter outlines manually.
Do not synthesize fake bold/medium.

Include the upstream OFL license text in an appropriate legal/licenses location in the repository/app distribution.

Do not expose or share raw font files in chat/report artifacts; keep them as project resources.

======================================================================
6. LINE HEIGHT / BASELINES
======================================================================

Onest has different vertical metrics from the current generic Android sans.

Inspect:
- title line spacing
- button vertical centering
- card title/caption baselines
- navigation label baseline
- chip text baseline
- input text baseline

Do not accept:
- text sitting visually low in buttons
- excessive top/bottom padding created by font metrics
- clipped accents/diacritics
- labels touching icons

Use explicit lineHeight / includeFontPadding decisions where justified.

Be careful with android:includeFontPadding:
do not disable it globally without checking Cyrillic glyph extents and clipping.

Prefer scoped use after visual verification.
