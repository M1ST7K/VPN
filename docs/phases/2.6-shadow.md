# Phase 2.6 — HotFox Shadow / Stealth & Resilience

Canonical product spec: `docs/HOTFOX_ROADMAP.md` section 2.6.

## Objective

Expand AUTO from “best server” to “best usable protected path” in the current network: server + transport + security + optional entry/exit.

Do not weaken TLS, REALITY, certificate verification or secret handling to raise connect rates.

## Path model

`ConnectionPath` is first-class: `serverGuid + transport + security + family + role`.

Supported transports (only if the shipped Xray build can configure them): TCP, RAW, WS, gRPC, XHTTP. Unknown networks are rejected, not advertised.

## Fallback

Bounded, generation-owned, cancelled by user disconnect:

1. preferred path;
2. alternate transport (same site when possible);
3. alternate server;
4. Shadow route when a dedicated entry profile exists.

Manual selection stays sticky. Retry cap is finite.

## Shadow AUTO UX

Default users see `Shadow: Авто` and `Подбираем защищённый маршрут…`, not VLESS/REALITY/XHTTP jargon.

## Security

Fallback never rewrites a REALITY/TLS profile to `none`/insecure TLS. Multihop loops (same node as entry and exit) are rejected.
