2. CANONICAL TECHNICAL CONTRACT — MUST SURVIVE UNCHANGED
====================================================================

Production VPN path conceptually remains:

Android apps
→ Android VpnService / TUN
→ HEV / tun2socks
→ local Xray SOCKS
→ Xray outbound
→ remote VPN server
→ Internet

`CONNECTED` / `Защищено` может появляться только из существующего canonical verified VPN session state.

Нельзя считать protected только потому что:
- VpnService запущен;
- TUN создан;
- Android показывает VPN key;
- Xray process запущен;
- SOCKS слушает;
- HEV запущен;
- сервер выбран;
- ping прошёл;
- закончилась UI animation.

UI не создаёт второй state machine.
UI не создаёт production `isConnected=true` самостоятельно.
UI только отображает существующую правду.

Сохрани без регрессии:
- VpnService/TUN lifecycle;
- Xray readiness/startup order;
- HEV/tun2socks lifecycle;
- protect/loop prevention;
- DNS leak safety;
- IPv6 route/fail-closed policy;
- clean disconnect;
- clean reconnect;
- session generation / stale callback rejection;
- bounded retry/failover;
- network-change handling;
- no duplicate session/service;
- AUTO persisted mode;
- AUTO resolved target;
- manual sticky selection;
- real latency/health only;
- invalid/maintenance/blocked candidate exclusion;
- Smart Routing;
- per-app include/exclude;
- domain/IP rules already supported;
- DNS/IPv6/LAN policy;
- Shadow;
- Autopilot;
- trusted-network logic;
- cellular/Wi-Fi policy;
- pause and manual-disconnect suppression;
- captive portal behavior;
