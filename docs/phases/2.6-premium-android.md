# Phase 2.6 — Premium Android Experience

## Objective

Make HotFox feel like a finished modern Android product without sacrificing the editorial visual direction or the truthful VPN state model.

## Information architecture

Primary phone navigation remains exactly:

`Соединение / Серверы / Подписка`

Settings is a secondary surface, not a fourth primary destination.

Do not restore drawer/side rail/competing nav.

## Connection screen

Keep a calm but useful hierarchy:

- HotFox/toolbar;
- large truthful status;
- timer/detail;
- selected mode + resolved server;
- route bars `Вы -> VPN -> Интернет`;
- routing summary;
- real upload/download session counters;
- concise subscription snapshot;
- one primary action.

State copy:
- `Не подключено`;
- `Подключаем…`;
- `Защищено`;
- `Переподключаем…`;
- actionable error title.

Connecting stages should be humanized rather than raw internal enum/code dumps.

## Error UX

Create/maintain a presentation mapper from structured engine errors to:
- title;
- one-sentence explanation;
- primary recovery action;
- optional secondary action;
- diagnostic code hidden in details.

Examples:
- no internet;
- permission missing;
- server unreachable;
- local tunnel failed;
- protected path verification failed;
- subscription has no available servers.

Do not make raw `HF-VPN-*` the main user message.

## Server screen

Preserve contemporary editorial rows:
- AUTO first;
- city/server;
- country/meta;
- real ping/unknown/testing/unreachable;
- favorite;
- clear selected state.

Keep filters/search compact.

Avoid legacy card-heavy UI.

## Subscription screen

Support phase-dependent states:
- no access;
- external active;
- HotFox active;
- expiring;
- expired;
- purchase pending/activation if commercial system exists;
- stale sync/backend failure.

For active access show what is real:
- status;
- expiry/remaining days;
- server count;
- traffic/quota if supplied;
- last sync;
- masked source/URL where appropriate;
- update/renew/manage actions.

## Onboarding

Keep short:

1. HotFox value proposition.
2. Choose `Купить HotFox` or `Добавить подписку` if commercial flow exists; otherwise manual setup.
3. Explain Android VPN permission immediately before system prompt.

After successful setup, go to the product; do not force a tutorial carousel.

## Empty/loading/stale states

Every async area should have intentional:
- initial;
- loading;
- content;
- empty;
- stale/offline;
- error;
- retrying.

Do not show an indefinite spinner when safe cached data exists.

## Visual system

Preserve:
- dark charcoal/purple-black background;
- warm cream/off-white text;
- restrained orange;
- green only for actual success;
- thin separators;
- disciplined spacing;
- premium editorial typography.

Avoid:
- generic giant rounded Material cards everywhere;
- neon/cyberpunk gradients;
- fake map/dashboard visuals;
- black-on-black default icons;
- Unicode symbols that render as missing squares.

Use explicit vector assets/tints.

## Spacing/touch

Use a coherent 4dp base grid with common 8/12/16/24/32 rhythm.

Touch targets >= 48dp.

Server rows generally 64–72dp.

Keep horizontal insets consistent across three primary screens.

## Accessibility

Required:
- TalkBack labels for actions/icons;
- selected server exposed semantically;
- decorative route bars hidden from accessibility tree;
- critical state communicated with text, not color only;
- logical focus order;
- large font support;
- sufficient contrast;
- no clipped bottom nav/plan cards;
- keyboard/D-pad basic sanity where practical.

## Reduced motion

Route animation/haptics must remain subtle.

When system animator scale is disabled/reduced:
- avoid constant pulsing;
- preserve state in a static visual form;
- do not lose semantic information.

Pause route animation when view is detached/offscreen.

## Haptics

Optional restrained feedback:
- primary connect tap;
- real connection success;
- important error sparingly.

No vibration spam.

## Android system integration

After core stability:

### Quick Settings tile
- connect/disconnect through canonical command path;
- truthful connecting/connected/disconnected state;
- no stale shortcut that bypasses server/permission validation.

### Foreground notification
- truthful state;
- resolved server;
- disconnect action;
- optional retry where appropriate;
- no sensitive source URL/token.

### Optional later
- trusted-network auto-connect;
- temporary pause 5/15/60 min;
- launcher shortcut;
- home-screen widget only if product demand exists.

## Auto-connect/trusted Wi-Fi

If implemented:
- opt-in;
- modes such as off / untrusted Wi-Fi / all networks;
- respect explicit manual Disconnect cooldown;
- handle SSID permission/version limitations;
- do not collect unnecessary network/location history;
- captive portal flow must not claim protected traffic while login is blocked.

## Sideload update discovery

For local distribution, the app may notify about newer builds.

Requirements:
- signed/HTTPS update manifest;
- exact version/SHA/checksum;
- prevent downgrade/tamper;
- no silent install;
- signing certificate continuity;
- stable/beta/dev channel separation in later operations phase.

## Localization

Move user-visible strings out of Kotlin/XML literals into resources.

Support at least:
- Russian;
- English;
- correct plurals/long strings.

Do not permanently rely on disabling translation lint as the product grows.

## Screenshot regression

Add deterministic UI-state fixtures in test-only code and capture reference states:
- disconnected;
- connecting;
- connected;
- error;
- servers/AUTO/manual;
- no subscription;
- active subscription;
- purchase state if available.

Matrices:
- 360dp-ish;
- 412dp-ish;
- API 24 sanity;
- modern API;
- RU/EN;
- larger font.

Production code must not fake telemetry just to make screenshots pretty.

## Responsive/system bars

Audit:
- gesture navigation;
- 3-button nav;
- edge-to-edge/current Android behavior;
- landscape sanity;
- 600dp+ basic max-width/readability.

No separate tablet product is required initially, but layouts must not break.

## Exit gate

The core user journey should be understandable without technical knowledge, accessible on supported Android versions, visually consistent with HotFox, and protected by repeatable screenshot/emulator regression tests without inventing network state.
