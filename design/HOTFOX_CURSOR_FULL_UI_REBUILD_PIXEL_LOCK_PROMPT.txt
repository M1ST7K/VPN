2. ЧТО ИМЕННО ВОССОЗДАЁТСЯ
==========================================================================

В APK реализуй содержимое дисплея внутри нарисованного телефона.
Внешние заголовки листов, рамка и блики корпуса, камера, callout-панели,
номера, соединительные линии, footer «UI/UX SPEC» — не элементы приложения.
Не превращай приложение в просмотрщик презентационных листов.
Не рисуй внутри APK второй телефон или системный hole-punch.

Если делаешь отчётные presentation boards, оригинальная внешняя часть листа
может служить окружением для честной вставки ФАКТИЧЕСКОГО скриншота приложения.
Это только отчёт. Такой лист не заменяет actual PNG, UI tree и тесты действий.
Не выдавай оригинальную картинку или imagegen-рендер за скриншот из APK.

Внутри приложения:
- текст — настоящий текст с доступностью и масштабированием;
- кнопки — настоящие Android controls с обработчиками;
- список — настоящий прокручиваемый список;
- поля — настоящие редактируемые поля;
- переключатели — реальные настройки, если их изменение поддержано;
- данные — существующий state/repository/backend;
- иллюстрация может быть растровым asset, интерфейс целиком — нет.

3. НЕИЗМЕНЯЕМАЯ ТЕХНИЧЕСКАЯ ОСНОВА
==========================================================================

Сохрани production datapath:
Android apps → VpnService/TUN → HEV/tun2socks → local SOCKS → Xray
→ VPN outbound → remote server → Internet → response.

Не меняй applicationId com.hotfox.vpn, minSdk 24, signing identity,
формат данных пользователя, ядро, версии сетевых зависимостей или протоколы
ради визуальной задачи. Не начинай миграцию на другой UI framework.

Сейчас проект восстанавливается bootstrap/bootstrap_source.sh в V2rayNG/.
V2rayNG/ — генерируемый игнорируемый каталог, не источник поставки изменений.
Сохраняй изменения в versioned overlay bootstrap/hotfox_2_2_0/ и в необходимых
существующих patch/bootstrap scripts. Проверь повторную чистую реконструкцию.
Изменение только локального V2rayNG/ не считается реализацией задания.

Изучи реальные точки привязки:
- ui/MainActivity.kt — UI и часть команд; НЕ весь файл является «только UI»;
- ui/HotfoxOnboardingActivity.kt;
- ui/GroupServerFragment.kt;
- ui/MainRecyclerAdapter.kt;
- ui/HotfoxRoutingPrivacyActivity.kt;
- ui/HotfoxAutopilotActivity.kt;
- res/layout/activity_main.xml и другие текущие layouts;
- res/values*, drawable, темы и ресурсы;
- HotfoxEngineFacade.snapshot() — существующая UI-граница состояния.

Пути выше относятся к bootstrap/hotfox_2_2_0/app/src/main/.
Проверяй фактические символы на текущем SHA перед изменением.
Не вводи UI-доступ к внутренностям coordinator в обход фасада.

Обязательные инварианты:
T01. Canonical session, generation и claim ownership сохраняются.
T02. Защищено только после существующей production path verification.
T03. VpnService старт/стоп остаются сериализованными и идемпотентными.
T04. Animation completion не запускает CONNECTED и не пишет protection state.
T05. UI lifecycle/recomposition/navigation не создают вторую сессию.
T06. Native Xray sockets не возвращаются в собственный TUN.
T07. Последний fix claim teardown inside admission commit lock сохраняется.
T08. Ошибка bindProcessToNetwork не превращается в успешный старт.
T09. Запуск HEV/SOCKS/Xray и rollback сохраняют прежний порядок/владение.
T10. Старый callback не переписывает новую generation.
T11. Отмена во время старта не позволяет отложенному start воскресить VPN.
T12. Явный disconnect остаётся сильнее Autopilot/retry/route-restart.
T13. Underlying network binding освобождается только правильным владельцем.
T14. DNS не получает скрытый direct fallback при заявленной защите.
T15. IPv6/NAT64 и ::/0 сохраняют действующую fail-closed политику.
T16. LAN bypass не начинает обходить IPv6-защиту.
T17. AUTO — persisted mode, первый пункт списка, не фиктивный GUID.
T18. Ручной выбор не переключается в AUTO сам собой.
T19. Resolved AUTO server показывается из текущей сессии.
T20. Старый ping после handover не становится измерением новой сети.
T21. Невалидные/недоступные/entitlement-blocked кандидаты не оживают ради списка.
T22. CUSTOM/POLICYGROUP/PROXYCHAIN валидируются существующим корректным путём.
T23. Генератор Xray использует один canonical routing snapshot.
T24. outboundTag/balancerTag разрешаются из фактической конфигурации.
T25. DOMAIN/CIDR/direct/proxy/block и include/exclude сохраняют семантику.
T26. Обновление подписки не уничтожает working profile при сетевой ошибке.
T27. Внешние HTTPS-конфигурации сохраняют предусмотренную независимость от backend.
T28. Payment/entitlement authoritative на backend, return URL — не proof.
T29. Keystore/storage migration и existing secret redaction сохраняются.
T30. Shadow не ослабляет TLS/REALITY и не выдумывает поддержку сервера.
T31. Autopilot сохраняет pause, manual-stop, trusted networks и captive portal.
T32. Notification/QS остаются привязаны к canonical truth и текущим командам.
T33. Offline entitlement, device registry, signed control plane сохраняются.
T34. Settings screen не меняет настройки просто при открытии/отрисовке.
T35. Android always-on/lockdown не симулируются локальным boolean.
T36. Обновление UI не удаляет диагностические, import/export или прежние действия.

Запрещён «рефакторинг ядра заодно». Если выявлен реальный дефект, зафиксируй
его отдельно; не маскируй последствия новым UI и не объявляй регрессию принятой.
Минимальное изменение технического интерфейса допускается только при доказанной
необходимости и с отдельным diff, объяснением и focused regression evidence.
Это не разрешение изменить сетевую семантику.

6. ИЗМЕРЕНИЕ И РЕСУРСЫ
==========================================================================

Для каждого screen ID заполни measurements/<ID>.json:
- source path и SHA-256;
- размер листа;
- координаты дисплея в координатах оригинала;
- app-controlled viewport отдельно от рамки/SystemUI;
- source pixel → canonical pixel → dp transform;
- safe insets, status/navigation bars;
- bounds каждого H1/body/CTA/card/row/artwork;
- text baselines, font family/файл/hash, weight, size, lineHeight, tracking;
- line breaks и точные статические строки;
- colors sampled from source с координатами и контекстом;
- radii, strokes, divider coordinates, icon bounds;
- z-order, clipping, alpha, background assets;
- fixture ID, target device profile, animation sample time;
- неизвестные величины со статусом UNRESOLVED, не выдуманные числа.

Геометрия каждого телефона на листах разная. Один общий crop для 18 файлов
недопустим. Размеры измерять на полном оригинале, не на preview из чата.
Pixel source не равен dp; округление переводов проверять обратным отображением.
Не угадывай шрифт по фразе «Inter / SF Pro / похожий».
Нужен точный доступный шрифт с кириллицей и сохранённой лицензией.
При отсутствии оригинального font asset измерь кандидаты и запиши остаточный diff.
Не называй подобранный шрифт точным без доказательства.

Исходный ZIP содержит flattened boards, а не Figma/PSD/layered assets.
Нельзя обещать восстановление скрытых лис/фона/букв пиксель в пиксель,
если нужные пиксели перекрыты кнопкой, линией-выноской или корпусом телефона.
Извлечение неизменённого декоративного фрагмента допустимо, когда он пригоден
без перерисовки и не содержит UI-текст/controls/чужие выноски.

8. АНИМАЦИЯ И СОСТОЯНИЯ, КОТОРЫХ НЕТ НА СТАТИЧНОМ МАКЕТЕ
==========================================================================

Один статичный кадр не задаёт duration/easing/полную траекторию.
Зафиксируй measured keyframe и реализуй минимальное спокойное движение,
не меняющее layout и не добавляющее новых объектов.
Параметры timing документируй как implementation choice, не «взято с изображения».

Для 06 допустима анимация существующего кольца/точек/активной stage line.
Не вращать всю лису, весь экран или unrelated rings.
Не заменять artwork loading bars из текстовой выноски.
UI animation не задерживает технический stop/error/protection loss.
Animation clock отдельно от session clock. В tests возможно остановить только UI clock.

Для navigation/sheets: сохранить Android Back, swipe dismiss и state restoration.
Повторный tap не открывает несколько копий, не запускает несколько imports.
Lifecycle cancellation не роняет service, который принадлежит приложению/системе.
Соблюдай reduced animation/system animator duration scale; no busy loops.

Обязательные состояния сверх 18 эталонных кадров:
- empty, loading, success, error, unavailable capability;
- revoked/denied VPN permission;
- no subscription, invalid/expired subscription, backend unavailable;
- no servers, no search results, stale ping;
- no internet, timeout, cancellation, network handover;
- keyboard shown, long names, large font, process recreation;
- pending payment, restore failed, offline entitlement;
- unknown Android always-on/lockdown status.

Для них используй уже измеренные primitives и существующее честное поведение.
Не объявляй pixel match к несуществующему изображению.
Не выдумывай backend/state для красивого error/success сценария.

9. ACCESSIBILITY И РАЗНЫЕ УСТРОЙСТВА
==========================================================================

Pixel lock проверяется в объявленном canonical capture profile.
На других density/size/fontScale система закономерно растеризует иначе;
это не право поменять дизайн canonical кадра и не обещание одинаковых пикселей
на разных физических экранах.

Сохрани TalkBack, настоящие labels/roles/selected/checked/enabled states.
48dp hit targets можно обеспечивать невидимой областью касания.
При fontScale >1.0 сохранять доступность CTA/прокрутку/читаемость,
не отключать системное масштабирование ради screenshot match.
При gesture/3-button navigation соблюдать WindowInsets без двойного padding.
Русский locale, реальные кириллические glyphs, нет □/missing glyph.
Не форсировать LTR для пользовательских данных, если это ломает Android text.

Проверь baseline profile и доступные representative варианты малого/высокого
экрана, API 24 и современного API, fontScale 1.0/1.3/2.0.
Это layout/accessibility evidence, отдельное от нулевого diff canonical profile.
Не требуй физический телефон для начала всей UI реализации.

==========================================================================

Нулевой допуск: changed_pixels == 0 и max_channel_delta == 0
для ВСЕХ пикселей заранее объявленной сравниваемой области.
Ни «1px», ни «0.1%», ни высокий SSIM не считаются точным совпадением.
Нельзя добавлять tolerance flag и менять эталон, чтобы пройти проверку.

Не путай три результата:
A. Originals integrity: файлы действительно те, что дал владелец.
B. Reference fidelity: app pixels сравнены с исходным reference target.
C. Regression stability: сегодняшняя реализация совпала со вчерашним screenshot.
B обязателен. Один C не доказывает верность изображениям владельца.

До реализации заморозь comparison contract для каждого ID:
- точный source SHA;
- app viewport crop/координаты;
- renderer/API/system image/width/height/density/fontScale;
- locale/timezone/night mode/insets/navigation mode;
- font file/hash и color space;
- test-only fixture state, frozen date/session clock/traffic/latency;
- точный animation sample time, settled-layout condition;
- source-to-canonical transform и алгоритм, если неизбежен;
- список пикселей вне app ownership, если такие исключены, с причиной.

Оригиналы не редактировать. Производный crop сохранять отдельно с provenance.
Для разницы размеров нет автоматического resize. Для смещения нет auto-align.
Если render profile нельзя привести к declared target, результат BLOCKED,
а не «всё равно PASS, масштаб отличается».

SystemUI, рамка корпуса, camera cutout и внешние выноски принадлежат не APK.
Отделение этих областей — явное определение app viewport, не полное совпадение
всего исходного board. Любой excluded pixel делает claim FULL_BOARD_IDENTITY
неприменимым. Отчёт обязан указать точную область проверки.

Не маскировать динамический текст: для visual test использовать deterministic
state на границе presentation с теми же strings/fonts/geometry, что в production.
Так проверяются и цифры, и baseline, и контейнер. Fixtures только debug/androidTest
или отдельный test renderer, без release entry point и реальной VPN симуляции.

Без controlled clock/fixture визуальный тест runtime screen помечается отдельным
smoke result. Нельзя вырезать из comparison все «неудобные» значения.
Значения sample URL/expiry/ping никогда не заменяют реальные production values.

Никакие masks для app-controlled text/CTA/icons/artwork/layout не разрешены.
Нельзя «приблизить» reference под actual blur/filter/resample/paint operations.
Если JPEG/antialias/font/flattened artwork оставляют ненулевой diff, честно
запиши FAIL или BLOCKED с причиной и областью; не ослабляй acceptance.
Для недоступного original asset запиши конкретно, что необходимо для достижения 0.
Не зацикливайся бесконечно при доказанной нехватке исходников: выполни независимые
части, собери доказательства и оставь честный остаточный blocker.

Для каждого кадра публикуй:
<ID>_reference.png, <ID>_actual.png, <ID>_overlay.png, <ID>_diff.png,
<ID>_capture.json, <ID>_metrics.json, relevant UI hierarchy / action evidence.
Actual — из APK/render path данного commit. Не reference, не генерация и не макет.
Metrics: dimensions, pixel count, changed pixels/percent, channel MAE/max,
diff bbox, ref/actual SHA-256, source SHA, candidate SHA, fixture/profile IDs.

Проверка родственных экранов не заменяет самостоятельную проверку 18/18.
Все 18 должны иметь actual и независимый status.
MISSING/NOT_EXECUTED/BLOCKED — не ноль отличий.

11. ПРИЛОЖЕННЫЕ ПРОВЕРКИ
==========================================================================

Из корня репозитория:
python3 verification/ui_rebuild/verify_reference_lock.py integrity
python3 verification/ui_rebuild/verify_reference_lock.py core

Первая команда сверяет originals SHA, dimensions и содержимое ZIP.
Вторая сравнивает protected technical files с зафиксированной runtime-базой.
core PASS означает отсутствие изменений этих файлов, не доказательство VPN E2E
и не доказательство корректности callbacks внутри изменённого MainActivity.
Добавленные runtime files и bootstrap/CI изменения проверяются отдельным diff.

Для уже подготовленных одинаковых по размеру target/actual:
python3 verification/ui_rebuild/verify_reference_lock.py pixels \
  --reference PATH_TO_DECLARED_REFERENCE_PNG \
  --actual PATH_TO_ACTUAL_PNG \
  --out DIRECTORY_FOR_EVIDENCE

Comparator не генерирует screenshots, не знает источник переданного reference
и не сертифицирует 18 экранов одним вызовом. Capture provenance и source binding
обязательны в отчёте. Self-comparison — только test comparator, не приёмка UI.
Comparator возвращает nonzero при любом изменённом пикселе/ошибке/размере.
Нет tolerance, auto-mask, blur или auto-update-golden.
Не меняй verifier/lock JSON ради прохождения.

12. ПОРЯДОК РЕАЛИЗАЦИИ
==========================================================================

Этап A — baseline + source analysis:
verify original assets, record SHA, reconstruct existing app, run baseline,
map actions, establish measured profile/geometry/assets, document source conflicts.

Этап B — presentation primitives:
точные colors/fonts/backgrounds/icons, controls, rows, sheets, nav variants;
не ломать existing commands. Добавить test-only fixture entry mechanism.

Этап C — 01–04 onboarding, 05–07 connection, 08–09 import,
10–11 servers, 12 subscription, 13 settings, 14–15 routing,
16 Autopilot, 17 Shadow, 18 system protection.
Порядок групп может учитывать зависимости ресурсов, но результат — все 18.
После каждой группы: targeted build, relevant action/state tests,
actual screenshots, diff, исправление выявленных отклонений.
Не тратить время на полный unrelated test suite после каждого 1dp исправления.

Этап D — интеграция и regression:
полный navigation path, сохранение настроек, реальные action callbacks,
reconstruction from clean checkout, release exclusion of test fixtures,
существующие functional/unit/lint/static/security gates.

Этап E — финальный evidence:
18 screenshots + diffs + metrics + accessible APK + SHA provenance,
полный список outstanding mismatch/blocker, exact commit CI links.
Зелёный build без screenshot comparison не закрывает UI задачу.

13. ТЕХНИЧЕСКАЯ РЕГРЕССИЯ: КОНКРЕТНЫЕ GATES
==========================================================================

Сначала используй команды/параметры актуального CI и инструкции bootstrap.
Не запускай неизвестные/не существующие скрипты по догадке.
Существующие Android команды выполняются из reconstructed V2rayNG/:
./gradlew :app:assemblePlaystoreDebug
./gradlew :app:testPlaystoreDebugUnitTest
./gradlew :app:lintPlaystoreDebug
./gradlew :app:assemblePlaystoreRelease

Из корня репозитория:
bash bootstrap/verify_payload.sh
bash bootstrap/verify_hotfox_2_2_0.sh
python3 verification/static_check_2_2_0.py

И актуальные meaningful secret/runtime/static gates из workflow.
Старый grep на три вкладки разрешено обновить под явное новое UI требование
с эквивалентной semantic navigation test. Это не разрешение ослабить проверку
AUTO row/state/security, удалить тест или отключить lint целиком.
Не менять trusted AI_REVIEW_PHASE_ID/reviewer scripts в этой UI задаче.

Обязательные focused regression сценарии:
R01 connect → verified → UI Protected;
R02 connect → cancel на каждой startup boundary;
R03 rapid connect/stop/connect и late callback;
R04 protected → error/revoke → отсутствие false Protected;
R05 Activity recreation/background не дублируют start/stop;
R06 Wi-Fi/cellular handover и ручной stop во время restart;
R07 AUTO persisted/manual sticky/no candidates/stale latency;
R08 manual subscription import/paste/QR/file/cancel/invalid/TLS failure;
R09 managed/external entitlement и forged checkout return;
R10 routing apply/rollback/reconnect и include/exclude;
R11 DNS/IPv6/LAN settings без неявного обхода;
R12 Autopilot pause/manual-stop/trusted/captive portal;
R13 Shadow no insecure fallback;
R14 notification/QS/action state совпадают с canonical session;
R15 always-on Settings return/unknown state;
R16 installation/update с сохранением existing user state;
R17 отсутствие test fixtures/секретов в release artifact;
R18 все ранее доступные действия отражены в interaction map.

Повторно используй существующие тесты; добавляй тест на реальную новую boundary,
а не на повторение constants, очевидных из реализации.
Не требуй приватную подписку в Git. При доступном authorized runtime fixture
прогони существующий VPN E2E harness. Без доступа — NOT_EXECUTED с причиной.
Для device-wide proxy proof нужен клиентский трафик через TUN и внешний IP
до/во время/после подключения при подходящей тестовой топологии.
SOCKS-only request и эмульторный screenshot не доказывают device-wide VPN.

profile_id,fixture_id,width,height,changed_pixels,changed_percent,
mean_channel_delta,max_channel_delta,diff_bbox,status,notes

Статусы по отдельности:
ORIGINALS_INTEGRITY = PASS / FAIL;
SCREEN_IMPLEMENTATION = IMPLEMENTED / PARTIAL / NOT_STARTED;
REFERENCE_PIXEL_MATCH = EXACT / FAIL / BLOCKED / NOT_EXECUTED;
FUNCTIONAL_REGRESSION = PASS / FAIL / NOT_EXECUTED;
CORE_SNAPSHOT = UNCHANGED / CHANGED;
ANDROID_BUILD = PASS / FAIL / NOT_EXECUTED;
RUNTIME_VPN_E2E = PASS / FAIL / NOT_EXECUTED;
PHYSICAL_DEVICE_E2E = PASS / FAIL / NOT_EXECUTED.

EXACT допустим только при 0 changed pixels, 0 max delta, валидном provenance
и заранее объявленной области. Не используй EXACT для «основные элементы похожи».
18/18 EXACT нельзя ставить при 17 PASS и одном missing/blocked.
IMPLEMENTED не значит EXACT. EXACT с fixture не значит runtime E2E PASS.

TECHNICAL_CORE_TOUCHED.txt должен содержать NONE, если это подтверждено diff.
Если core менялся: каждый файл, зачем, изменение semantics, regression evidence.
Отдельно review командных блоков внутри UI файлов, которые hash gate не защищает.
Сохрани baseline failures и незавершённый runtime gate PR #4 честно.

APK должен быть построен из финального candidate SHA; записать SHA-256 файла,
variant/version/package и CI run/artifact URL. Не ссылаться только на mutable
hotfox-dev-latest, которое может перезаписываться другой веткой.
Подписанный релиз не выпускать без существующего предусмотренного процесса.
Предоставить соответствующие исходники/лицензионные уведомления вместе с APK.

15. АВТОНОМНОЕ ПРОДОЛЖЕНИЕ И ОСТАНОВКА
==========================================================================

Работай самостоятельно между группами: implement → build → compare → fix.
При CI failure исправь причину и продолжи. Не объявляй завершение при запуске CI.
Используй обычные commits во время реализации. Финальный coherent checkpoint
ревью — по действующей политике после зелёных required gates, не на каждый commit.
Не используй [hotfox-phase-exit] для этого пакета задания и промежуточных UI правок.
Не мержи main/PR и не меняй protections/reviewer policies ради «не останавливаться».

Если есть инфраструктурный blocker: сначала выполни всё независимое.
Если нельзя воспроизвести отдельный asset без оригинала: продолжай остальные
экраны, подготовь actual/diff и точный список недостающих исходников.
Не спрашивай «продолжать?» и не проси владельца нажать Build за тебя.
Не задавай повторно уже решённые вопросы о стиле — владелец выбрал эти изображения.

Разрешённый финал успешного UI задания:
«18/18: нулевой diff в объявленных canonical app viewports; реальные controls
и callbacks проверены; технические gates перечислены; runtime/device статус указан».
Такой финал допустим только при фактических доказательствах.

Иначе финал:
«Реализовано X/18; EXACT Y/18; остаются конкретные FAIL/BLOCKED и причины;
готовые независимые части, APK/commit/evidence доступны».
Не писать «1:1 ни пикселя» без нулевых результатов по всем целям.
Не писать RELEASE READY без полного существующего runtime/physical release gate.
